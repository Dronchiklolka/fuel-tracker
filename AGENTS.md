## Важная особенность запуска

На компьютере пользователя есть несколько виртуальных сетевых адаптеров: VPN, WSL, Docker/Hyper-V и другие.

Обычная команда:

```bash
npm run start
```

может выбрать неправильный IP-адрес и Expo Go на телефоне не сможет скачать bundle.

Поэтому для запуска проекта всегда использовать:

```bash
npm run start:lan
```

Этот скрипт уже прописан в package.json и задаёт правильный IP:

```bash
REACT_NATIVE_PACKAGER_HOSTNAME=192.168.1.100
```

Не заменяй `npm run start:lan` на `npm run start`, если пользователь явно не попросил.

Не используй `npx expo start --tunnel`, если пользователь явно не попросил. Tunnel через ngrok уже давал ошибку подключения.

## Как проверять изменения

После изменений обязательно выполнить:

```bash
npm run lint
```

Если нужно проверить запуск приложения, использовать:

```bash
npm run start:lan
```

Если менялись зависимости Expo, можно дополнительно выполнить:

```bash
npx expo-doctor
```

## Правила работы с проектом

1. Не переписывай весь проект сразу.
2. Не делай всё приложение за один запрос.
3. Работай маленькими шагами: один экран или одна логическая задача за раз.
4. Перед изменениями кратко объясняй план.
5. Не удаляй файлы без явной необходимости.
6. Не меняй архитектуру проекта без согласования.
7. Не добавляй тяжёлые UI-библиотеки без необходимости.
8. Не подключай backend, Supabase, RevenueCat, AI API или авторизацию, пока пользователь отдельно не попросит.
9. Не храни API-ключи в мобильном приложении.
10. Если нужны моковые данные, клади их отдельно и явно называй mock-данными.

## Правила по Figma

Перед реализацией экрана:

1. Найти нужный frame в Figma.
2. Получить цвета, отступы, размеры, typography и ассеты через Figma MCP, если доступно.
3. Если Figma MCP недоступен, прямо сказать об этом.
4. Не придумывать дизайн от себя, если есть данные из макета.
5. Если ассет недоступен, использовать временную заглушку и явно написать TODO.

## Журнал проекта и Windows-команды

Перед началом каждой задачи обязательно читать:

1. `AGENTS.md`;
2. `PROJECT_LOG.md`, если файл существует.

После каждой будущей задачи обязательно обновлять `PROJECT_LOG.md`: кратко записывать дату, суть задачи, что изменилось, какие файлы затронуты, какие проверки запускались и их результат.

На Windows для дочерних npm/npx-команд использовать `npm.cmd` / `npx.cmd`. Если команда запускается из Node.js через `child_process.spawn` и нужен `shell: false`, `.cmd`-файл может потребовать безопасный запуск через `cmd.exe` с аргументами массивом, без сборки всей команды в одну строку.
